# ticket-to-pr

Complete development pipeline: takes a Jira ticket (or task description) and delivers a ready-to-merge PR.

## Pipeline Steps

This agent was auto-generated by AgentFlow from a pipeline definition.

### Step 1: Parse Input (AI Task)

Parse the pipeline input and determine the ticket type. Accept any of these formats:
- Jira ticket key: `$JIRA_PROJECT_KEY-300`, `$JIRA_PROJECT_KEY-155`
- Jira URL: `$JIRA_BASE_URL/$JIRA_PROJECT_KEY-300`
- Plain description: e.g. "add session timeout feature"

Extract the Jira key if present. If a plain description is given, flag that no Jira ticket exists so subsequent steps skip Jira-specific logic.

**Inputs**: ticketInput

**Outputs**: jiraKey, hasJiraTicket, rawDescription

### Step 2: Fetch Jira Ticket (AI Task)

If a Jira key was parsed, use the Atlassian MCP tools to fetch the full ticket details:
- Summary (title)
- Description (requirements)
- Issue type (Bug, Task, Story)
- Priority

This becomes the source of truth for what to implement. If no Jira key exists, use the raw description as the requirements and infer the issue type (default to Task).

**Inputs**: jiraKey, hasJiraTicket, rawDescription

**Outputs**: summary, issueType, description, priority

### Step 3: Create Worktree (AI Task)

Fetch latest remote and create a new worktree branched from origin/$BASE_BRANCH. Run the following bash commands:

1. `git fetch origin $BASE_BRANCH`
2. Determine BRANCH_NAME from the ticket info:
   - Bug/Fix → `fix/$JIRA_PROJECT_KEY-XXX-kebab-description`
   - Feature/Story/Task → `feature/$JIRA_PROJECT_KEY-XXX-kebab-description`
   - No Jira → `fix/kebab-description` or `feature/kebab-description`
3. Compute WORKTREE_DIR: `.worktrees/{branch-name-with-slashes-replaced-by-dashes}`
4. Clean slate — if the worktree already exists, remove it first:
   ```
   git worktree remove "$WORKTREE_DIR" --force
   git branch -D "$BRANCH_NAME" 2>/dev/null || true
   ```
5. Create the worktree: `git worktree add "$WORKTREE_DIR" -b $BRANCH_NAME origin/$BASE_BRANCH`

Output the branchName and worktreePath (absolute path to the worktree directory) so downstream nodes can use them.

**Inputs**: summary, issueType

**Outputs**: branchName, worktreePath

### Step 4: Bootstrap Worktree (Shell Command)

WORKTREE="$WORKTREE_PATH"

if [ -z "$WORKTREE" ]; then
  echo "ERROR: WORKTREE_PATH not set"
  exit 1
fi

# Backend: copy vendor if exists, otherwise composer install
if [ -d "backend/vendor" ]; then
  cp -r backend/vendor "$WORKTREE/backend/vendor"
else
  cd "$WORKTREE/backend" && composer install --no-interaction
fi
cp backend/.env "$WORKTREE/backend/.env" 2>/dev/null || true

# Frontend: copy node_modules if exists, otherwise npm install
if [ -d "frontend/node_modules" ]; then
  cp -r frontend/node_modules "$WORKTREE/frontend/node_modules"
else
  cd "$WORKTREE/frontend" && npm install
fi

echo "Bootstrap complete for $WORKTREE"

**Inputs**: worktreePath

**Outputs**: bootstrapComplete

### Step 5: Plan Implementation (AI Task)

1. Read the Jira ticket requirements (or task description)
2. Explore the relevant existing code to understand patterns
3. Identify which files need to change
4. Plan the approach

If the scope is large (10+ files), present the plan for human approval before proceeding.

**Inputs**: summary, description, issueType, worktreePath

**Outputs**: implementationPlan, filesToChange, isLargeScope

### Step 6: Approve Implementation Plan (Approval Gate)

Review the implementation plan before proceeding. This gate activates when the scope is large (10+ files) or when the requirements are ambiguous. Approve to continue with implementation, or reject with feedback to revise the plan.

**Inputs**: implementationPlan, filesToChange, isLargeScope

**Outputs**: planApproved

### Step 7: Implement Changes (AI Task)

Write the code following project conventions:

**Backend (Laravel/PHP)**:
- Services in `backend/app/Services/`
- Enums in `backend/app/Enums/` — PascalCase string values ALWAYS
- Events in `backend/app/Events/`
- API routes in `backend/routes/api.php`
- Use existing patterns — read similar code first

**Frontend (Next.js/TypeScript)**:
- Components in `frontend/src/components/`
- Hooks in `frontend/src/hooks/`
- Contexts in `frontend/src/contexts/`
- TanStack React Query for data fetching
- Laravel Echo for WebSocket subscriptions

Follow the implementation plan exactly. Read existing similar code before writing new code.

**Inputs**: implementationPlan, worktreePath, description

**Outputs**: changedFiles, implementationSummary

### Step 8: Write Tests (AI Task)

Write tests following project conventions:

**Backend (Pest)**:
- Use `test()`, `expect()`, `beforeEach()`, `RefreshDatabase`
- Feature tests: `backend/tests/Feature/{Domain}/{Name}Test.php`
- Unit tests: `backend/tests/Unit/{Domain}/{Name}Test.php`
- Use existing factories from `backend/database/factories/`

**Frontend (Vitest + React Testing Library)**:
- Co-locate tests with components
- Test user interactions and rendering

Ensure tests cover the main functionality and edge cases from the ticket requirements.

**Inputs**: changedFiles, implementationSummary, worktreePath

**Outputs**: testFiles

### Step 12: Fix Test Failures (AI Task)

If any tests failed:
1. Read the failing test AND the source code it tests
2. Determine the cause — bug in code, outdated test, or bad test
3. Fix accordingly
4. Re-run the failing tests to verify the fix

If tests pass on the first run, this node is a no-op and passes through immediately.

**Inputs**: backendTestResult, frontendTestResult, worktreePath

**Outputs**: allTestsPassing

**Retry**: up to 3 attempts, 10s delay

### Step 13: Update Changelog (AI Task)

Update the root `CHANGELOG.md` with a new entry at the TOP (below any header):

```markdown

### Added / Changed / Fixed / Removed
- **Backend**: Description ($JIRA_PROJECT_KEY-XXX)
- **Frontend**: Description

---
```

Rules:
- New entry at TOP, below header
- Prefix lines with `**Backend**:` / `**Frontend**:` / `**Admin**:`
- Include Jira key if applicable
- If frontend-only changes, also update `frontend/CHANGELOG.md`

**Inputs**: implementationSummary, changedFiles, summary, jiraKey

**Outputs**: changelogUpdated

### Step 14: Commit Changes (Git Operation)

cd "$WORKTREE_PATH" && git add -A && git commit -m "${ISSUE_TYPE}: ${SUMMARY} (${JIRA_KEY})" && git add CHANGELOG.md frontend/CHANGELOG.md 2>/dev/null && git commit -m "docs: update changelog" 2>/dev/null; git rev-parse HEAD

**Inputs**: worktreePath, changelogUpdated, summary, issueType, jiraKey

**Outputs**: commitHash

## Jira
[$JIRA_KEY]($JIRA_BASE_URL/$JIRA_KEY)

## Test plan
- [ ] Backend tests pass
- [ ] Frontend tests pass
- [ ] Build succeeds"

**Inputs**: worktreePath, branchName, commitHash, summary, issueType, jiraKey

**Outputs**: prUrl
